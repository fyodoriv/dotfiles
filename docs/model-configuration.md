## Model Configuration

Each agent keeps its own default model. Do not infer a cross-agent model change from a change to one agent.

| Agent | Default tier | Identifier string | Config location | Owner |
|-------|--------------|-------------------|-----------------|-------|
| **Claude Code** | XHigh | `claude-opus-5-5` + `effortLevel: "xhigh"` (per-machine override below) | `~/.claude/settings.json` | **dotfiles** (`.chezmoiscripts/run_after_claude-settings-model.sh` + `modules/claude/doctor.sh` → `claude.model_default`; `Agentfile.yaml` `defaultModel`/`defaultEffort` for agentbrew model sync) |
| **Cursor** | Claude Code parity | `claude-opus-5-5-xhigh` (derived from `~/.claude/settings.json` `model=claude-opus-5-5`, `effortLevel=xhigh`) | `~/.cursor/cli-config.json`, Cursor IDE reactive storage (`~/Library/Application Support/Cursor/User/globalStorage/state.vscdb` → `aiSettings.modelConfig`), and `cursor/subagentModelOverrides` | **dotfiles** (`.chezmoiscripts/run_after_cursor-agent-parity.sh` + `modules/cursor/doctor.sh` → `cursor.model_parity`) |
| **Cursor agents** | Editor settings parity | vim keybindings, font size/family, line numbers, word wrap from `~/Library/Application Support/Cursor/User/settings.json` | `~/.cursor/cli-config.json` (`editor.vimMode`), `state.vscdb` → `cursor/glass.editorPreferences`, `glass.display.settings` | **dotfiles** (same script + `modules/cursor/doctor.sh` → `cursor.agent_settings_parity`) |
| **Codex** | _carve-out_ | n/a — Codex is OpenAI-first (default `o3` / `gpt-5.X`); Anthropic isn't a first-class provider in `~/.codex/config.toml` | `~/.codex/config.toml` `model = "..."` (TOML top-level) | **operator** (carve-out — Codex defaults to OpenAI models; routing Codex through an Anthropic provider is out of scope for the tier-1 default) |
| **Gemini CLI** | _carve-out_ | n/a — Gemini CLI uses Gemini-family models only, not Anthropic | `~/.gemini/settings.json` | **operator** (carve-out — different model family entirely; "Opus 5.5 XHigh" doesn't translate) |
| Per-persona `ANTHROPIC_MODEL` | — | varies | minsky `personaRunner.ts` | **minsky** (pipeline override) |

**Identifier-string gotchas (these have bitten us before — verify before changing):**

- **Claude Code** rejects effort suffixes such as `-max` outright — `claude-opus-5-5-max` errors at startup. Claude Code's CLI separates the base model id from the thinking level: model = `claude-opus-5-5` (with optional `[1m]` suffix for 1M context), thinking level = `effortLevel` in `~/.claude/settings.json` (persistable values are `low`, `medium`, `high`, `xhigh`; `max` is only available in-session via `/effort max`). The `~/bin/claude` wrapper installed by `.chezmoiscripts/run_after_claude-wrapper.sh` strips any leaked `ANTHROPIC_MODEL` env var so Claude Code uses its own configured selection — don't try to pin Claude Code's model via env var, it won't take. The settings.json pin is installed by `.chezmoiscripts/run_after_claude-settings-model.sh` (idempotent `jq` merge that preserves every other key Claude Code writes — hooks, MCPs, plugins, etc.). agentbrew writes the same two keys from `Agentfile.yaml` `defaultModel`/`defaultEffort`; `tests/claude-model-agentfile-consistency.bats` keeps both sources equal.
- **Per-machine override** (an org overlay or one Mac): set chezmoi data `claude_model` / `claude_effort` in `~/.config/chezmoi/chezmoi.yaml` (kept across `chezmoi init`), or export `DOTFILES_CLAUDE_MODEL` / `DOTFILES_CLAUDE_EFFORT`. Env wins over chezmoi data, key by key. Use chezmoi data for a lasting override: the scheduled sync and doctor LaunchAgents do not read your shell env. An unset key keeps the base default. The effort must be one Claude Code can persist (`low`, `medium`, `high`, `xhigh`); any other value keeps the base default and prints a warning. `claude.model_default` asks the pin script for the resolved pair (`--print-desired`), and Cursor parity reads `~/.claude/settings.json`, so both follow the override. Set the same pair as `defaultModel` / `defaultEffort` in the overlay `Agentfile.yaml`, so agentbrew writes the same values.
- **Cursor** does not use Claude Code's split `model` + `effortLevel` shape. The equivalent Cursor model id is the joined slug (`claude-opus-5-5-xhigh`); any `claude-opus-N-M` model maps the same way. Newer Cursor IDE catalogs list the base model (`claude-opus-5-5`) and take effort as a model parameter; for those, the script writes the base id with `effort` set and the catalog's first value for every other parameter, while the CLI and subagents keep the joined slug. The parity script seeds the IDE's SQLite-backed `aiSettings.modelConfig` for Agent/Composer surfaces from Claude Code, then mirrors that editor Agent config into Cursor CLI agents (`~/.cursor/cli-config.json`) and subagent overrides (`cursor/subagentModelOverrides` in the same SQLite DB). It intentionally leaves Cmd-K at Cursor's default because current Opus catalog entries do not advertise Cmd-K support.
- **Cursor agents** inherit editor UX from the same `settings.json` dotfiles symlinks into `~/Library/Application Support/Cursor/User/`. The agent parity script mirrors vim mode into `~/.cursor/cli-config.json` (`editor.vimMode`), Glass agent editor prefs into `cursor/glass.editorPreferences` (`keybindings`: `vim` when vscodevim settings are present), and font sizing into `glass.display.settings`. Color theme for in-IDE Glass editors follows `workbench.colorTheme` from that same settings file; the headless `cursor-agent` CLI has no theme field in `cli-config.json` and instead inherits terminal colors (see Cursor CLI docs — use `TERM_THEME=light` on light terminals if auto-detection fails).
- **Vitest extension discovery** is guarded in `cursor/settings.json` via `vitest.configSearchPatternExclude` (skips doc mirrors, worktrees, scrub dirs) plus `vitest.logLevel: info`. Doctor check: `cursor.vitest_discovery_guard`. See `docs/troubleshooting.md#vitest-extension-floods-output--spawns-hundreds-of-processes`.
- **Codex** is a Cognition / OpenAI CLI — its `-c model="..."` example uses `o3` and the `--oss` flag routes through local providers (Ollama / LMStudio). Routing Codex through an Anthropic provider would require a custom `model_providers` config + an Anthropic API key + a translation layer; it's not in scope for the tier-1 "Opus 5.5 XHigh" default (`Agentfile.yaml` sets `modelOverrides.codex: null`). Codex stays at its built-in OpenAI default; the user picks the model per-invocation with `-m gpt-5.5` / `-m o3` / etc.
- **Gemini CLI** isn't installed on the M3 Max box (`command -v gemini` returns nothing). It would use Google's Gemini family natively; the Anthropic-shaped Opus tier doesn't apply. Carve-out documented; revisit if the user starts using Gemini regularly.

**Debugging:** wrong model? Check, in order:
1. For Claude Code: `cat ~/.claude/settings.json | jq '.model, .effortLevel'` → `"claude-opus-5-5"` and `"xhigh"` (or this machine's override). The fix path is `dotfiles-doctor --module claude --fix` (which sources `.chezmoiscripts/run_after_claude-settings-model.sh`) — never hand-edit settings.json, Claude Code rewrites it on shutdown.
2. For Cursor: `dotfiles-doctor --module cursor --fix` runs `.chezmoiscripts/run_after_cursor-agent-parity.sh`, which maps Claude Code's `claude-opus-5-5` + `xhigh` to Cursor's `claude-opus-5-5-xhigh`, mirrors the editor Agent model into Cursor CLI agents and `cursor/subagentModelOverrides`, and syncs agent vim/fonts/glass keybindings from editor `settings.json`.
