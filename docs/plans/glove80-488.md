# Glove80 support: registered preparation

Issue #488 supplies a command and 13 synthetic controls, but omits their
factory-keymap fixture. Before implementation, add the controls and a pinned
upstream fixture in a preparation change. The controls skip by default while
the command is absent; `GLOVE80_REQUIRE_IMPLEMENTATION=1` makes that absence
a failure, so the baseline is observable without claiming a passing feature.

Goal: give the user repeatable profile and pairing guidance. Question: can the
supplied command satisfy all 13 frozen synthetic controls with no live
Bluetooth changes during tests? Prediction: available-command behavior moves
from 0/13 to 13/13, including denial, timeout and renamed-device controls.

Measurement: `GLOVE80_REQUIRE_IMPLEMENTATION=1 heavy-run bats
tests/glove80.bats`, then `heavy-run make check`. Success is 13/13 controls,
the full gate and independent review. Any failed control, unsafe unapproved
profile clearing, or unverified live-pairing claim rejects the approach.
This does not measure real pairing or establish a keyboard's actual layout.
Keep real device pairing separate and do not clear an existing profile without
explicit approval.

The keymap fixture comes from MoErgo's MIT-licensed official repository at
commit `34888be8c9d9a3d5b168a502b8b191ba43b4a1f3`; preserve its license and
source reference. Review the supplied patch, its handling of Bluetooth data,
actions parity and settings before any implementation.

Anchor: Basili, Caldiera and Rombach (1994), Goal Question Metric; Munafò et
al. (2017), preregistration; issue #488's reported synthetic controls.

Before implementation, add controls for five reviewed risks: an already
connected device must not prove or save a requested profile; a failed or hung
Bluetooth probe must report unknown and terminate within its registered
bound; logs must not expose unrelated device names and must use private
permissions; an unknown keymap must not produce a guessed key or suggest
clearing a profile; and CLI actions must be discoverable through the existing
registry. For the profiler timeout, use a scratch hung stub and require process
termination within 10 seconds with a 1-second configured bound, including
cleanup. All six added safety cases and the original 13 must pass: 19/19, with no skips. Any wrong-profile
save, unrelated-device disclosure, unbounded probe or unapproved clear
instruction rejects the approach. The supplied patch is a proposal, not
evidence that these controls pass.

The original successful-pair fixture starts disconnected, receives explicit
user confirmation, and then observes a connection. Treat any profile saved in
that path as user-asserted, not discovered from Bluetooth. An already connected
keyboard or a connection without that assertion does not establish a profile.
The preparation's absence-only skip must be removed with implementation. The
timeout control requires the repository's coreutils `gtimeout`; a missing tool
fails qualification rather than silently skipping it. Scratch tests set HOME
and XDG paths and never use real Bluetooth data.

The hung-probe control rejects watchdog and signal exits and checks monotonic
elapsed time below nine seconds. It checks the fixture's direct process only;
it does not prove complete cleanup of arbitrary descendant processes.

Before implementation, align profile storage and confirmation with the shared
settings table and `lib/confirm.sh`. Preserve the 19 behavior controls, but
exercise confirmation through a scratch pseudo-terminal rather than accepting
piped text as a human confirmation. Profile reads and writes must use `dotfiles
config`, and the paired-state control must inspect that scratch configuration.
Success remains 19/19 without skips and the existing config and action parity
suites passing. Any write outside the scratch home, unconfirmed pairing, lost
configuration value, or broken action gate rejects the approach.

Before the next fix, add five red controls: malformed successful profiler
output must be unknown; a log symlink must not change its target; an invalid
wait limit must not open settings; an unreadable keymap must not save a
profile; and repeated slow probes must stay within a registered short total
deadline. For the deadline use a 2-second total and require return within
6 seconds without the outer watchdog terminating it. All five controls and
the existing 19 must pass; any false not-paired, altered symlink target,
premature UI action, incorrect save or deadline miss rejects the approach.

Before changing the next boundary, add controls that require successful
Bluetooth output to identify an enabled controller, and that a custom
`--keymap` stays in use through an interactive pairing save. Header-only or
disabled-controller output must be unknown. The custom-keymap control must
return the selected custom key after a scratch connection and save the
user-asserted profile. All controls must pass with the prior 24; either a
false not-paired result or wrong-layout save rejects the approach.

Before the next repair, add scratch controls for a symlinked log parent, a
hardlinked log file, and log failure before profile save; each must leave its
sentinel or configuration unchanged. Add slow-open and slow-poll controls
that exercise the entire post-confirmation operation, not only the initial
probe. With a two-second configured deadline, each must end within six seconds
without relying on the test watchdog. All these controls and the previous
24 must pass. Any changed sentinel, unexpected saved profile or deadline miss
rejects the approach. A profile confirmation is a user assertion, not proof of
the keyboard firmware's selected profile.

Before continuing, require structured enabled-controller and device-section
evidence before reporting not paired; truncated data remains unknown. Test a
FIFO keymap and reject it without blocking. Test a writable log directory
and a symlink inside an ancestor path, plus log failure before any setting
write. Test the deadline after confirmation, including a slow opener, probe,
and config save. The exact qualification is all registered controls with no
skips; a false not-paired result, unsafe log target, blocked FIFO or deadline
miss rejects the approach. Do not claim protection against concurrent path
replacement unless a descriptor-relative no-follow implementation is proven.

A new approach will use descriptor-relative, no-follow file operations for
the private log rather than validating a pathname and reopening it. Before
implementation, add a deterministic scratch race: after the parent directory
is opened, replace its pathname with a symlink to a sentinel directory. The
writer must not change the sentinel. Also retain leaf symlink, hardlink,
owner/mode and ordinary append controls. Measure with `heavy-run bats
tests/glove80-private-log.bats tests/glove80.bats`. Success requires every
registered control with no skips and no sentinel change; any redirected
write, changed sentinel, invalid log permission or missing test rejects the
approach. This is a new design, not a claim that the previous pathname checks
were race-safe.
