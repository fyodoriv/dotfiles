# Future hook effective-input audit

The retained RSS runs do not prove which helper and executable chains the
measured hook actually selected. A separate startup probe is not an observation
inside the measured hook. Do not use a later probe to repair those runs.

A future method must bind one run ID to the source and harness revisions, the
independent audit, the checkout identity, and the reviewed hook, bootstrap,
installer and helper bytes. It must capture the actual post-startup selection
and helper-source boundary in that run, or independently prove an equivalent
constrained selection. Record the effective root, relevant startup and path
choices, helper identity, and selection-relevant absence of alternatives.

For every external executable actually used, the audit must cover the selected
path, each symlink hop, bounded file identity and bytes, shebang and recursively
selected interpreter. Native binary and system-library dependencies need either
an independent audit or an explicit system-trust assumption. Reopen and compare
the relevant source, startup and tool identities before and after the run.
An independent reviewer must compare the retained observations with the audit,
run admission, and result. Keep sensitive paths and environment values private.

Missing, ambiguous, changed or unbounded inputs make the run inconclusive.
Boundary checks cannot prove continuous immutability, arbitrary descendant
completion or absence of host interference. A separate Bash probe alone does
not establish the measured hook's selections. In-process observation or a
constrained alternative may change behavior or timing: register and review it
separately, test parity, and use an equivalent method on both sides. Do not
start a new timing run until descendant completion and input closure have an
independently reviewed method. This document specifies evidence still needed;
it does not claim an implementation or a qualified measurement.
